Sending books to a device

The Send to device command (from the Book menu, or Ctrl+D in the book list context menu; see Book menu and Context menus) copies the checked books into the device folder, converting them to the required format if necessary. The device itself and the format are configured beforehand in Devices and export.

Where the books are written

The destination folder is either the one already configured as the default or, if the settings ask for the path every time, one you pick in a dialog immediately before the send; the choices there can include MTP devices (a phone or a reader connected as a portable device rather than as a drive). If any of the checked books belong to an online collection and have not been downloaded yet, MyHomeLib downloads them first — exactly as it does when you open them for reading; see Reading books.

Conversion

MyHomeLib handles the FB2, FB2.ZIP and TXT formats on its own. LRF, EPUB, PDF and MOBI need separate converters, which ship alongside the program in the converters\… subfolders (not every build includes them); if the converter you need is not on disk, MyHomeLib checks for that up front, before any copying starts, and reports the missing converter instead of silently writing nothing.

File and folder names

The file name and the subfolder inside the device folder are built from templates with substitutions such as %f (author), %t (title), %s (series), %n (number in the series) and %g (genre) — the percent sign goes in front only, with no closing "%". This is the same template mechanism used to sort files during import (see Importing FB2 books). Part of a template can be enclosed in square brackets — only one macro is allowed inside the brackets, and the whole fragment appears in the file name only if that macro's value is not empty (for example, the default file template [%n - ]%t puts the number and a "-" separator in front of the title only when the book has a number in its series; otherwise the title alone remains). The templates themselves are edited in Devices and export, where you will also find the full list of substitutions. If a file of the same name already exists on the device, MyHomeLib does not overwrite it but appends "(1)", "(2)" and so on to the name.

What the progress window shows

While the copying runs you see a counter reading "Files written: N of M". If some file could not be processed, you are asked whether to carry on with the remaining files, and whether to remember that answer for the rest of the current send (so you are not asked again on every subsequent failure).

The error log

If there were errors during the send, a separate message after the operation gives their number and the path to the log file (export_errors.log in the program's working folder); new errors are appended to the existing file rather than replacing it.
