Portable version

Running MyHomeLib from a removable drive

MyHomeLib offers no separate portable distribution: portable mode is the same program, copied together with its folder onto a flash drive or another removable disk and started without being installed. Administrator rights are needed only by the installer (see Installation); the executable itself does not require them.

Which files have to sit next to the executable

Required: the sqlite3.dll library — the program will not start without it. MyHomeLib also always looks in its own folder for the genre lists genres_fb2.glst and genres_nonfb2.glst, whether the run is portable or ordinary. The folder of the bundled AlReader reader and the folders of the format converters are optional: without them the program starts normally, it is just that the default reader and conversion are unavailable until you point File types and readers at another path. The simplest and most reliable approach is to copy the whole folder of the installed program onto the removable drive, exactly as the installer laid it out.

How the program chooses between the portable and the installed data location

By default MyHomeLib keeps its settings and the system database in the %APPDATA%\MyHomeLib folder (for details see FAQ). To force the program to use its own folder instead, put an empty, extensionless file named uselocaldata next to MyHomeLib.exe — that file is what marks a portable run. An equally empty uselocaltemp file next to the executable moves the temporary files into a subfolder of its own ($tmp) as well; otherwise they are written to the Windows temporary files folder. The command line parameters uselocaldata and uselocaltemp have the same effect if you start MyHomeLib.exe from a shortcut with those arguments.

There is an automatic case, too: if the current Windows user has no %APPDATA%\MyHomeLib folder at all, MyHomeLib takes that as a sign of a portable run by itself and keeps its data next to the executable straight away, even without a uselocaldata file. It is not worth relying on that: one ordinary run of MyHomeLib on some computer (or one installation onto it) is enough to create the folder, after which a portable run on that same computer does need the uselocaldata file. So, for portable mode to be guaranteed on any computer, always keep the uselocaldata file next to the executable rather than counting on the automatic detection.

In portable mode the system database lives in a Data subfolder next to the executable (Data\user.dbs2), while the settings, collections.ini and the working logs sit in that same folder rather than in %APPDATA%.

Limitations

The uselocaldata marker moves only the settings and the system database; it does not take the temporary folder with it — that needs the separate uselocaltemp file. Without it, even in portable mode MyHomeLib uses the Windows temporary files folder of whatever computer it is running on rather than one of its own, so it does not quite vanish from the computer without a trace.

The paths to the device folder, the reading folder, the download folder, the import folder and so on are stored in the settings as ordinary absolute paths and do not adapt to a new drive letter: if the flash drive or external disk was given a different letter on another computer, those paths have to be set again.

A portable copy comes with no installer support: there are no Start menu shortcuts and no uninstall entry — you manage the folder (copying, moving, deleting it) by hand.
