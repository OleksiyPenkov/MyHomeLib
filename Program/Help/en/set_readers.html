File types and readers

The File types section of the settings dialog (see Program settings) is a table matching file extensions to viewer programs, and it is what the Read command works from; for more about how the reader is picked, see Reading books.

The list

The table has two columns — Extension and Path — and is managed with the three buttons below it:

Add
Opens a small Add file type window with a Type: field (the extension, without the dot — case does not matter) and a Path: field (the full path to the reader program; the Browse... button opens the standard file picker). The extension is required — without it the entry is not added; and if that extension is already in the list, a message says so and the entry is not added either.
Change
Opens the same window for the selected row (as does a double click on the row); you can change both the path and the extension itself.
Delete
Removes the selected row from the list without asking for confirmation.

If there is no reader for an extension

The list does not have to cover every file type in the collection: for an extension that is not in the table, MyHomeLib simply hands the file to whichever program Windows itself has registered for that extension (the ordinary file association) — exactly as it does for an entry with an empty Path field.

The built-in reader

MyHomeLib has no built-in reader of its own — "Read" always launches a separate program. All the installer does is put AlReader alongside it and, on first run (while the reader list is still empty), fill the table itself: it assigns AlReader to the fb2, doc, txt, htm and html extensions, and for four more — pdf, djvu, mht and chm — it also adds a row, but with an empty Path field, which, as described above, opens such a file with the program Windows has registered by default. This starting set is only a convenient initial state for the table: you are free to edit or delete any of it, like any other row.
