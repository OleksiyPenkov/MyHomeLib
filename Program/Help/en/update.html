Updating a collection

Updating means pulling fresh additions from the source of an online library into a collection you have already connected; it is not the same as syncing folders and files, which only checks what is already in the catalog against what is physically on disk or downloaded.

Two ways to update a collection

A collection can be updated either from the network or from a file you have on disk.

Updating from the network

This applies only to collections connected from the sources listed in the collections.ini file (see Installation) — that is, well-known online libraries such as lib.rus.ec or Flibusta; collections of your own are not updated this way. To check for updates and download them, use the Update collections command on the Tools menu (see Tools menu); the program can also check for updates on its own while it runs, if the settings allow it, and offer to download them.

Updating from a file

The Update collection from file... command on the Collection menu (see Collection menu) updates the active collection from a book list that you choose yourself. Unlike an update from the network, this works with any collection — including a private one that is not listed in collections.ini.

The file has to be a book list in INPX format. Such files often carry a .zip extension instead of .inpx (update.zip, for example) — both are accepted, because it is the same format.

In the dialog, point to the file with the Browse... button and, if you need it, tick Full reimport (clear the collection). The box is off by default, so an ordinary update adds records to the existing catalog.

The program neither modifies nor deletes the file you picked — it stays on disk after the update. The properties of the collection itself (its address, connection script and notes) are not changed by an update from a file either, even if the file contains values of its own for them.

What changes in the collection

There are two kinds of update. For an update from the network the kind is decided by the source; for an update from a file, by the Full reimport box:

  • Partial (incremental) — new and changed records from the update file are added to the collection's existing catalog, and the rest of the catalog is left alone.
  • Full — the collection catalog (books, authors, series, genres) is cleared completely first and then filled again from the update file.

If you interrupt an update with the Cancel button, all the changes are rolled back — the collection stays exactly as it was before it started. If the file you picked turns out not to be a book list, the program says so and leaves the collection unchanged.

What happens to your own data

Before a full update the program saves ratings, reading progress, reviews and the group membership of books (Favorites and To read included) separately, and restores them once the catalog has been filled again, matching books by their stable identifier (LibID) rather than by the internal number, which is reassigned from scratch during a full update. Data for books that are no longer in the updated catalog is lost along with the records for those books. A partial update needs none of this: existing catalog records are not deleted, so the user data attached to them stays in place without being saved and restored.

Do not confuse this internal user data with the list of collections in the system database — updating a collection does not affect that list.
