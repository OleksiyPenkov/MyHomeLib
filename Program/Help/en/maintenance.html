Database maintenance

The Collection → Maintenance submenu holds two commands that work directly on the database file of the active collection: Check database and Compact. Both run on the open collection as it is — you do not have to close the collection first.

Compact

Compacts the database file of the active collection, reclaiming the space left behind by deleted and modified records — the .hlc2 file can end up noticeably smaller afterwards. The command does not change the data in the collection.

The command runs without a progress window and blocks the main window while it works: on a large collection this can take a noticeable while, during which the program will look unresponsive. Wait for it to finish rather than killing it.

Check database

Runs an SQLite integrity check on the collection file and reports the result: either a message that the check found no errors, or the list of problems it found. The command only inspects the file — it changes nothing and repairs nothing.

Do not rely on this command to bring a damaged collection back to life — it tells you the file is broken, but it cannot fix it. SQLite does not repair damaged files automatically.

If a collection will not open or reports a database error

Since Check database does not heal the file and Compact only compacts a file that is already sound, the program has no real automatic recovery for a damaged collection file. The practical options are these:

  • if you have a backup copy of the .hlc2 file made before the damage, put that copy back in place;
  • if you have no backup — disconnect the damaged collection (without deleting the file, just in case) and connect or create it again: build it anew from an INPX file (Creating a collection), for instance, or fill it by importing the book files still on disk once more (Adding books to a collection).

This is the same recovery path that FAQ and Upgrading a previous version point to when a collection stops opening after MyHomeLib has been updated.
