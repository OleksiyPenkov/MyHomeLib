User data export and import

The Collection → Export → User data and Collection → Import → User data commands (see Collection menu) save to a file, and read back, the personal data tied to the books of the active collection — separately from the book catalog itself.

What goes into the file

The export takes only what belongs to the active collection:

  • for every book that has a rating, reading progress or a review (see Rating and read status) — those three values;
  • all the groups from the system database (Favorites and To read among them — see Groups and favorites), and for each group, those books of the active collection that belong to it.

The file is saved with the .mhlud2 extension. The import also understands the old text form of user data (the .mhlud extension, from earlier versions of the program) — it recognizes it by the file extension automatically, with no extra action needed.

How books are matched on import

Every record in the file is tied to a book by its stable identifier (LibID) — the same one used to match books when a collection is updated (see Updating a collection). This works even when the internal book numbers in the collection are no longer the ones they were at export time — after a repeated import from INPX or a full update, for instance. Groups are matched by name on import: if a group of that name already exists in the system database (and Favorites and To read always do), the books are added to that one; if not, a new group is created.

The import overwrites the rating and the reading progress only when the value in the file is non-zero — and it does so unconditionally, putting the new value over the existing one whether it is higher or lower than the current one. If the file has zero (or no value) for these fields, the rating and progress already in the collection are left alone — importing user data cannot reset them to zero.

When you need this

It is most useful before anything that may break the link between books and this data: reinstalling the program, moving a collection to another computer, or reimporting a collection from scratch. Because the link goes through LibID rather than the internal book number, the exported data comes back correctly even into a newly created or fully updated collection — provided the books in it carry the same LibIDs as before.
