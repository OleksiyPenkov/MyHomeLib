Deleting books

The Delete command (the Book menu or the context menu of the book list; see Book menu) behaves differently depending on the type of the active collection — and in one of the two cases it really does remove the book from the database for good. The command always asks for confirmation first, and the wording of the question tells you what is about to happen.

You cannot delete a book while viewing it through a group tab or through Favorites — the program will ask you to switch to the tab of the collection the book actually belongs to first. That is by design: groups are only a way of viewing books, not collections of their own; see Groups and favorites.

Online collection: Delete the downloaded files?

Here Delete does not touch the catalog at all. If the book file has already been downloaded to disk, MyHomeLib deletes only that file and marks the book as not downloaded; the catalog record itself, its rating, reading progress and group membership all stay as they were. You can always download the book again — see Downloading books.

Private or connected collection: deleting the record from the database

Here the book's record is removed from the collection catalog for good — the row is deleted from the database directly, with no recycle bin and no "deleted" flag that could be undone. Along with the book:

  • authors who are left with no other book linked to them after the deletion are removed from the database as well;
  • the book disappears from every group it belonged to, Favorites and To read included.

The only way to bring a deleted record back is to import it again (by re-importing the collection from INPX, say, or by scanning the files anew) — the program keeps no copy of the deleted book description anywhere.

Is the file deleted from disk

That depends on the Delete files when deleting books option in the settings (see Behavior):

  • the option is off — only the catalog record is deleted; the file stays on disk as it is (orphaned), and you can bring it back into the catalog later by importing it again;
  • the option is on — for a book in a non-FB2 format the file is always deleted; for a book in FB2 format only if the active collection is private. If the collection was connected from someone else's INPX and uses someone else's files, the file is left alone when the record is deleted, so that files the program does not really own are not touched.

When the file does get deleted, it is an ordinary Windows deletion that bypasses the recycle bin (the code for moving files to the recycle bin exists but is disabled as "behaving oddly") — such a file can only be brought back with data recovery tools, and the MyHomeLib help makes no promises there.
