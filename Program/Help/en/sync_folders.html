Syncing folders and files

The Collection → Maintenance → Synchronize files command reconciles the catalog of the active collection with what is actually on disk, and does so differently for local and online collections (see Collection types).

Local collections: finding files that have moved

The direction here is from disk into the database: the command changes nothing on disk itself, it only corrects the file references in the collection catalog, and it does that only for books whose file is not currently where the stored path says it is.

  1. First it builds a complete list of the files in the collection folder (with the size of each; for files inside ZIP archives, the size of the archive's contents).
  2. Then, for every book in the catalog, it checks whether its file exists at the stored path.
  3. If the file is not there, it looks through the list it has just collected for a file with the same name and size; if one is found, the book's path in the catalog is corrected to the new location.

So the only files it picks up are the ones that were moved elsewhere inside the collection folder with their name and size unchanged. New files that are not in the catalog yet are not added by this command — that takes a separate import (see Adding books to a collection). Files that turn up nowhere in the collection folder, and files whose name or size has changed, are not detected: the book's record stays in the catalog pointing at the old, missing path.

Online collections: the state of downloaded files

Here the direction is the other way round: the command checks whether each book's file really is on disk (that is, whether the book has already been downloaded) and corrects the "downloaded" mark in the catalog to match the facts. If a local file is found for a book that the library has marked as deleted, and deleting deleted books is turned on in the settings, the file is removed from disk and the "downloaded" mark is cleared.
