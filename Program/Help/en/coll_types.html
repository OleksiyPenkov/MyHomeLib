Collection types

Every collection has an internal type that determines how it stores books and which operations are available to it. The type is made up of two independent properties: location (local or online) and content (FB2 or non-FB2), plus whether it is a private collection of your own or an external library you have connected.

Local and online

This is the division by where the book files physically sit:

Local collection
The book files are stored on your own disk, in the folder specified when the collection was created. Private collections of your own are always local.
Online collection
The book files are not stored in advance — the program asks the library server (Flibusta, for instance) for them and downloads each book only when you open it or send it to a device.

Among other things, this difference decides which properties tab the Collection properties window shows, and what exactly the Synchronize files command does — see Syncing folders and files.

Content: FB2 or non-FB2

A collection stores its books either in FB2 format (with the matching standard genre tree) or in any other format — non-FB2 (with a separate genre tree of its own). See Genre lists.

Copying books between collections (Copying books between collections) works only for FB2 collections. The mechanism for automatic updates from the network (Updating a collection) is likewise designed for FB2 collections — during an update the genre lists are always parsed as FB2.

A private collection or a connected external library

Separately from location and content, a collection is either a private library of your own that you fill yourself, or a connected external library such as lib.rus.ec or Flibusta, whose book catalog was compiled outside MyHomeLib. Private collections are always local; external libraries can be either local (a local copy of a catalog, say) or online.

How the type is determined, and why it cannot be changed

The type is not a field you fill in directly — it follows from the way the collection was created in the wizard (Creating a collection):

  • for a new empty collection the type is always private, and its content (FB2 or not) is decided by your choice on the File format step;
  • for a collection built from an INPX file the type (private or external, local or online, FB2 or not) is read from the INPX file itself and set automatically, with no involvement from you;
  • for an existing .hlc2 file being connected, the type remains whatever the file recorded when it was created.

Once a collection has been created its type cannot be changed: the Collection properties window has no field for it, and no command in the program edits it. If you need a collection of a different type, create it afresh.
