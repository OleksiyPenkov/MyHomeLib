Upgrading a previous version

Installing a new version over the existing one

To update MyHomeLib you do not have to remove the old version first — just run the installer of the new version with the same bitness (x86 or x64, see Installation). The installer remembers the folder the program was installed into before and offers that folder by default, so the update happens in place. It replaces only the program's own files (MyHomeLib.exe, sqlite3.dll, the genre lists, the help and so on), and only where the file in the distribution is newer than the one already installed.

The x86 and x64 distributions are registered in Windows under one and the same application id, so an installer of the other bitness also recognizes the previous installation folder and offers to update the program there.

What is kept during an update

The installer does not touch the %APPDATA%\MyHomeLib folder, with one exception: it puts collections.ini there only if no such file exists yet, and never overwrites an existing one. So, after an in-place update, the program settings (myhomelib2.ini) and the system database (Data\user.dbs2 — the list of connected collections, the groups including Favorites, and the ratings and notes on books, see Key terms) are left as they were. The collection files themselves — the books and the .hlc2 files — the installer does not touch at all: they stay wherever you put them.

Backing up the system database before a major update

Before updating to a markedly newer version it is worth copying the system database file somewhere safe, just in case — by default that is %APPDATA%\MyHomeLib\Data\user.dbs2, and in portable mode it is Data\user.dbs2 next to the executable. If something goes wrong after the update, you can put that copy back in place of the damaged file.

If a collection will not open after the update

If some collection will not open or reports a database error after the update, try the tools described in Database maintenance. If it is the system database file with the list of collections that is damaged, put the backup copy you made before the update back in its place.
